# User flows

Пошаговые пути по ключевым сценариям. Первые шесть — обязательные сценарии ТЗ; проверять их нужно на свежей базе (`docker compose down -v && docker compose up --build -d`).

## 1. Создание мероприятия с новым видом спорта

**Кто:** Иван (`user@sport.ru`).

```mermaid
flowchart LR
  a["Создать"] --> b["Шаблон"]
  b --> c["Свой вид спорта: Петанк"]
  c --> d["Опубликовать"]
  d --> e["Автопроверка"]
  e --> f["Вид petank в каталоге и фильтрах"]
```

Название нормализуется в slug (`Воркаут` → `vorkaut`), вид попадает в общий каталог, фильтры и `GET /sports`. Мероприятие со своим видом спорта всегда проходит проверку ИИ.

## 2. Допуск организации и публикация

**Кто:** Клуб «Ладья» (`ladya@sport.ru`) и администратор (`admin@sport.ru`).

```mermaid
flowchart LR
  a["Ладья создаёт событие"] --> b{"Статус организации"}
  b -->|PENDING| c["403: ожидает одобрения"]
  c --> d["Админ одобряет"]
  d --> e["Ладья публикует"]
  e --> f["Событие на карте сразу"]
```

Новую организацию можно зарегистрировать на `/auth`: название, ИНН, ОГРН, КПП.

## 4. Участие по заявке

**Кто:** Иван (организатор) и Алексей (`pro@sport.ru`, участник).

```mermaid
flowchart LR
  a["Алексей подаёт заявку"] --> b["PENDING"]
  b --> c["Иван: Мои события, Я организую, Заявки"]
  c --> d{"Решение"}
  d -->|Принять| e["CONFIRMED + билет"]
  d -->|Отклонить| f["REJECTED + комментарий"]
  e --> g["Алексей видит новый статус"]
  f --> g
```

## 5. Уточнение условий в обсуждении

**Кто:** Ольга или Алексей и Иван (автор).

```mermaid
sequenceDiagram
  participant U as Участник
  participant S as Sportikus
  participant O as Организатор
  U->>S: Вопрос в обсуждении
  S->>O: Появляется в ленте (опрос раз в 8 секунд)
  O->>S: Ответ
  S->>U: Ответ со значком «Организатор»
```

Администратор может скрыть сообщение — остальные увидят «Сообщение скрыто модератором».

## 6. Снятие мероприятия с публикации

**Кто:** Администратор.

```mermaid
flowchart LR
  a["Админ: Мероприятия"] --> b["Снять с публикации + причина"]
  b --> c["Исчезает из каталога, карты, рекомендаций"]
  c --> d["Прямая ссылка: плашка с причиной"]
  d --> e["Запись закрыта"]
```

Пример: `/events/5`.

## 7. Билет и вход на мероприятие

**Кто:** участник и организатор.

```mermaid
flowchart LR
  a["Участие подтверждено"] --> b["Выдан код SPT-XXXXXXXX"]
  b --> c["Участник: Показать QR-билет"]
  c --> d["Организатор сканирует QR"]
  d --> e{"Результат"}
  e -->|SUCCESS| f["Допущен"]
  e -->|ALREADY_CHECKED_IN| g["Билет уже использован"]
  e -->|WRONG_EVENT| h["Билет от другого события"]
```

## 9. Автопроверка нового мероприятия

```mermaid
flowchart LR
  a["Создание"] --> b["Фильтр запрещённых тем"]
  b -->|ничего не нашёл| c["Опубликовано сразу"]
  b -->|сомнение| d["Проверка ИИ"]
  d -->|отклонено| e["Не опубликовано, автор видит причину"]
  d -->|одобрено| f["Опубликовано с пометкой ⚠"]
  d -->|ИИ недоступен| f
```

Подробности — в разделе [Автопроверка мероприятий](../technical/moderation.md).
