# User flows

Пошаговые пути по ключевым сценариям. Первые шесть — обязательные сценарии ТЗ; проверять их нужно на свежей базе (`docker compose down -v && docker compose up --build -d`).

## 1. Создание мероприятия с новым видом спорта

**Кто:** Иван (`user@sport.ru`).

```mermaid
flowchart LR
  a["Создать"] --> b["Шаблон"]
  b --> c["Свой вид спорта: Петанк"]
  c --> d["Опубликовать"]
  d --> e["Автопроверка"]
  e --> f["Вид petank в каталоге и фильтрах"]
```

Название нормализуется в slug (`Воркаут` → `vorkaut`), вид попадает в общий каталог, фильтры и `GET /sports`. Мероприятие со своим видом спорта всегда проходит проверку ИИ.

## 2. Допуск организации и публикация

**Кто:** Клуб «Ладья» (`ladya@sport.ru`) и администратор (`admin@sport.ru`).

```mermaid
flowchart LR
  a["Ладья создаёт событие"] --> b{"Статус организации"}
  b -->|PENDING| c["403: ожидает одобрения"]
  c --> d["Админ одобряет"]
  d --> e["Ладья публикует"]
  e --> f["Событие на карте сразу"]
```

Новую организацию можно зарегистрировать на `/auth`: название, ИНН, ОГРН, КПП.

## 5. Уточнение условий в обсуждении

**Кто:** Ольга или Алексей и Иван (автор).

```mermaid
sequenceDiagram
  participant U as Участник
  participant S as Sportikus
  participant O as Организатор
  U->>S: Вопрос в обсуждении
  S->>O: Появляется в ленте (опрос раз в 8 секунд)
  O->>S: Ответ
  S->>U: Ответ со значком «Организатор»
```

Администратор может скрыть сообщение — остальные увидят «Сообщение скрыто модератором».

## 10. Знакомство гостя и обучение нового пользователя

**Кто:** гость, затем новый пользователь.

```mermaid
flowchart LR
  a["Ссылка на мероприятие или адрес сайта"] --> b["Приветственная страница /welcome"]
  b --> c["Регистрация"]
  c --> d["Возврат на мероприятие по ?next="]
  c --> e["Обучающий тур: 5 шагов"]
  e --> f["Тест интересов: 6 шагов"]
  f --> g["Страница Для вас с подборкой"]
```

Гость не видит каталог: любой адрес, кроме `/welcome` и `/auth`, ведёт его на приветственную страницу, а после входа возвращает туда, куда он шёл. Тур можно пропустить и повторить из профиля («Обучение по сайту»); тест можно пройти позже кнопкой «Пройти тест».

## 11. Очередь на места

**Кто:** участник A (подтверждён), участники B и C (в очереди).

```mermaid
sequenceDiagram
  participant B as Участник B
  participant C as Участник C
  participant A as Участник A
  participant S as Sportikus
  B->>S: Записаться, мест нет
  S->>B: Статус WAITLISTED
  C->>S: Записаться, мест нет
  S->>C: Статус WAITLISTED
  A->>S: Отменить участие
  S->>B: Уведомление: освободилось место
  S->>C: Уведомление: освободилось место
  B->>S: Занять место
  S->>B: CONFIRMED и билет
  S->>C: Уведомление: место заняли
```

Таймеров нет: место получает первый, кто откликнулся. Организатор заявку из очереди подтвердить не может.

## 12. Приглашение друга

**Кто:** Иван и его друг Алексей.

```mermaid
flowchart LR
  a["Иван: Позвать друзей на карточке"] --> b["Список друзей с состояниями"]
  b --> c["Выбор друзей и сообщение"]
  c --> d["Алексею приходит уведомление со ссылкой"]
  d --> e["Алексей открывает мероприятие и записывается"]
```

Друзьям, которых уже звали, и тем, кто уже идёт, приглашение повторно не отправляется.

## 13. Напоминание о мероприятии

```mermaid
flowchart LR
  a["Участие подтверждено"] --> b["До начала меньше 24 часов"]
  b --> c["Фоновая задача раз в 5 минут"]
  c --> d["Уведомление: Мероприятие уже завтра"]
  d --> e["Колокольчик и страница уведомлений, ссылка на мероприятие"]
```

Напоминание одно на участника и мероприятие; получают только подтверждённые участники опубликованных мероприятий.

## 14. Повторяющееся мероприятие

**Кто:** организатор.

```mermaid
flowchart LR
  a["Создать: Повторять событие, интервал в днях"] --> b["Мероприятие опубликовано"]
  b --> c["Время окончания прошло"]
  c --> d["Организатор: Завершить событие"]
  d --> e["Текущее занятие в архиве"]
  d --> f["Следующее занятие опубликовано, дата сдвинута на интервал"]
```

Участники на следующее занятие не переносятся: они записываются заново.
