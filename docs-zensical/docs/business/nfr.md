# Нефункциональные требования

Таблица показывает, как каждое требование выполнено в текущей версии и где проходит граница.

| Область | Требование | Как выполнено |
|---------|------------|---------------|
| Масштаб | Работа по всей стране, а не в одном городе | Геопоиск на PostGIS с GiST-индексом по опубликованным событиям; каталог ограничен областью (центр + радиус до 300 км) и 500 событиями; клиент запрашивает видимую область карты |
| Время | Корректное время в любом часовом поясе | Время хранится в UTC; клиент показывает по часовому поясу площадки и подписывает «местное»; ввод при создании трактуется как местное время площадки; 44 города со справочником поясов |
| Производительность | Быстрый ответ карты и рекомендаций | Кэш списка мероприятий для карты в Redis (TTL 60 с, версия данных `map:version`); кэш рекомендаций на пользователя на 2 минуты; ограниченные выборки кандидатов (300 на источник); тяжёлые расчёты в фоне |
| Консистентность | Нельзя выдать последнее место дважды | Все операции с местами — под `SELECT … FOR UPDATE` на строке мероприятия |
| Безопасность | Аутентификация и авторизация | JWT (срок 24 часа), без сессий, пароли BCrypt; `/api/v1/admin/**` — только `ROLE_ADMIN`; права на объекты проверяются в сервисах |
| Безопасность | Безопасная загрузка файлов | Только JPG, PNG, WebP до 5 МБ; имя файла — случайный UUID; отдельный каталог и volume |
| Безопасность | Защита от злоупотреблений | Автопроверка новых мероприятий; уникальность ИНН и ОГРН; текст мероприятия передаётся ИИ как данные (защита от prompt injection) |
| Отказоустойчивость | Сбой внешних сервисов не ломает продукт | Недоступен Redis — запросы идут в БД; недоступен ИИ — мероприятие публикуется с пометкой ⚠; нет ключа 2GIS — заглушка вместо карты |
| Предсказуемость | Единый формат ошибок | `{"error": {"code", "message"}}`, статусы `400/401/403/404/409` |
| Наблюдаемость | Состояние системы | `/actuator/health`, `/actuator/info`, `/actuator/metrics`; Swagger UI и OpenAPI JSON |
| Переносимость | Запуск одной командой | `docker compose up --build -d`: PostgreSQL + PostGIS, Redis, backend, frontend (Nginx) |
| Сопровождаемость | Изменение схемы без потери данных | Flyway-миграции V1–V8 и повторяемая `R__demo_data.sql`; Hibernate в режиме `validate` |
| Масштабируемость | Работа нескольких экземпляров бэкенда | Фоновые задачи берут `pg_try_advisory_xact_lock` и выполняются ровно в одном экземпляре |
| Качество | Автоматические проверки | Юнит-тесты бэкенда (Maven) и фронтенда (Vitest). См. [Тестирование](../technical/testing.md) |
| Интерфейс | Адаптивность и темы | Светлая и тёмная темы, нижняя навигация на телефоне |

## Известные упрощения

CORS открыт для всех источников; загрузки лежат на диске; кэш рекомендаций локален процессу; обсуждение обновляется опросом. Что менять при росте нагрузки — в [Ограничениях и развитии](../technical/limitations.md).
