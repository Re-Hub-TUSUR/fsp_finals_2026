# Покрытие ТЗ

Документ сопоставляет требования ТЗ с реализацией. Для шести обязательных сценариев «выполнено» означает, что сценарий проходит на свежей базе при ручной проверке. Для остальных возможностей «реализовано» описывает то, что есть в коде и API; тестами они покрыты в разной степени (см. [Тестирование](../technical/testing.md)).

## Шесть обязательных сценариев

Все проверки — на свежей базе: `docker compose down -v && docker compose up --build -d`.

| № | Сценарий | Статус | Как проверить |
|---|----------|--------|---------------|
| 1 | Создание мероприятия с новым видом спорта | Выполнено | Войти как Иван, «Создать», «+ Свой вид спорта», ввести «Петанк». Вид получает slug `petank`, появляется в фильтрах и `GET /sports` |
| 2 | Допуск организации и публикация | Выполнено | «Ладья» пытается создать событие — блокировка (`403`). Администратор одобряет организацию, «Ладья» публикует сразу, без премодерации |
| 3 | Свободное присоединение | Выполнено | Ольга открывает «Воркаут: тренировка и разбор базы» (свободный вход) и записывается — «Участие подтверждено» сразу |
| 4 | Участие по заявке | Выполнено | У «Дворового футбола 5x5» есть заявка Алексея. Иван принимает или отклоняет её в «Мои события — Я организую — Заявки»; Алексей видит новый статус |
| 5 | Уточнение условий (обсуждение под событием) | Выполнено | Ольга или Алексей пишет вопрос под «Дворовым футболом 5x5», Иван отвечает — ответ со значком «Организатор». Есть демо-диалоги. Администратор скрывает сообщение |
| 6 | Снятие мероприятия с публикации | Выполнено | Администратор: «Мероприятия — Снять с публикации» с причиной. Событие исчезает из каталога, карты и рекомендаций; по прямой ссылке — плашка с причиной, запись закрыта |

## Сверх обязательного

| Возможность | Статус | Комментарий |
|-------------|--------|-------------|
| Конструктор мероприятий на данных (JSON-схема шаблонов) | Реализовано | Новый формат — строка в `event_templates`, без правок кода. См. [Конструктор](../technical/constructor.md) |
| Рекомендации на масштаб страны | Реализовано | PostGIS, четыре источника кандидатов, объяснимое ранжирование, сигналы с затуханием. См. [Рекомендательная система](../technical/recommendations.md) |
| Автопроверка мероприятий (фильтр + ИИ) | Реализовано | Покрыта тестами; ИИ вызывается вне транзакции, при недоступности автор не блокируется. См. [Автопроверка](../technical/moderation.md) |
| Электронные QR-билеты и отметка на входе | Реализовано | Код `SPT-XXXXXXXX`, пять исходов проверки; сканер на весь экран с фонариком, фото и счётчиком отмеченных |
| Очередь на места | Реализовано | Статус `WAITLISTED`, освободившееся место получает первый откликнувшийся |
| Уведомления, приглашения друзей и напоминания | Реализовано | Центр уведомлений, `EVENT_REMINDER` за сутки до начала, приглашения на мероприятие |
| Повторяющиеся мероприятия и CSV-экспорт участников | Реализовано | Следующее занятие создаётся при завершении текущего; экспорт на странице управления |
| Приветственная страница, обучающий тур и тест интересов | Реализовано | Гость видит лендинг, новый пользователь проходит тур и тест из шести шагов |
| PWA | Реализовано | Установка, офлайн-оболочка и билеты без сети на доверенном HTTPS. См. [PWA](../technical/pwa.md) |
| Друзья, подписки на организации, достижения | Реализовано | Видно «Идут друзья» на карточке |
| Архив завершённых мероприятий | Реализовано | Завершает только организатор и только после времени окончания |
| Кэш карты в Redis | Реализовано | Необязателен: без Redis запросы идут в БД |
| Тёмная тема, адаптивная вёрстка, экспорт `.ics` | Реализовано | — |

## Что не реализовано

Честный список — в [Ограничениях и развитии](../technical/limitations.md). Главное:

- Push-уведомления. PWA реализовано, но офлайн и установка как приложения работают только с доверенным сертификатом — см. [PWA](../technical/pwa.md).
- Уведомления об ответах в обсуждении; обсуждение обновляется опросом раз в 8 секунд, без WebSocket.
- Сбор интересов в самой форме регистрации: интересы собирает тест, который предлагает обучающий тур после регистрации (а также профиль и страница рекомендаций).
- Напоминание только одно, за сутки до начала; расписание повторяющихся мероприятий наперёд не строится.
- Рекомендации — взвешенная формула, а не обученная модель: реальных данных для обучения пока нет.

## Известные риски для демонстрации

- Ключ 2GIS встраивается при сборке фронтенда; без него вместо карты показывается заглушка.
- Без ключа RouterAI автопроверка работает только на словаре, а сомнительные мероприятия публикуются с пометкой ⚠.
- Демо-данные создаются миграциями; тестовые мероприятия, созданные вручную во время проверки, остаются в базе до её пересоздания.
