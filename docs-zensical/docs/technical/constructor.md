# Конструктор мероприятий

Создание мероприятия (`/events/new`) собирается из блоков, а формат мероприятия описывается **данными, а не кодом**.

## Блоки формы

1. **Шаблон** (`GET /api/v1/templates`): «Тренировка», «Игра / матч», «Турнир», «Забег» (только для организаций), «Интеллектуальная игра», «Поход», «Мастер-класс» (не спорт) и «Свободный формат». Шаблон задаёт значения по умолчанию (вместимость, режим записи, уровень, длительность), набор дополнительных полей и вопросы участнику.
2. **Вид спорта.** Выбор из списка или «+ Свой вид спорта». Название нормализуется в slug (`Воркаут` → `vorkaut`) и сразу попадает в общий каталог и фильтры; дублей не создаётся.
3. **Свои параметры.** Произвольные пары «название — значение» поверх шаблона.
4. **Анкета участника.** Организатор сам добавляет вопросы (текст, число, выбор, да или нет), на которые отвечает подающий заявку.
5. **Данные организатора** (только для организаций; контакты обязательны): контактное лицо, телефон и e-mail, сайт или регламент, площадка, медицинская справка и страховка, список документов, призы, программа, инфраструктура, условия отмены, партнёры. Если заданы требования, участник подтверждает ознакомление при подаче заявки.
6. **Место и время.** Точка выбирается кликом по карте; время вводится по местному времени площадки (город и часовой пояс определяются по точке).

Публикует мероприятие пользователь — от своего имени; организатор — от имени организации, только после одобрения администратором (иначе `403`).

## Типы полей

`TEXT`, `TEXTAREA`, `NUMBER`, `SELECT`, `MULTISELECT`, `BOOLEAN`. Каждое поле описывается `FieldDef`:

| Атрибут | Смысл |
|---------|-------|
| `key` | Идентификатор: латиница, цифры и `_`, начинается с буквы, до 40 символов; в рамках формы уникален |
| `label` | Название до 100 символов |
| `type` | Один из шести типов |
| `required` | Обязательность |
| `options` | Варианты для `SELECT` и `MULTISELECT`: от 1 до 20, без пустых и повторов |
| `unit`, `placeholder`, `help` | Единица измерения, подсказка, пояснение |

## Валидатор

`FieldValidator` проверяет и описания полей (то, что определил автор), и значения, введённые по этим описаниям. Поэтому формы мероприятия и заявки полностью управляются данными.

- Не более 12 полей в форме; вариант ответа не длиннее 100 символов.
- Ограничения длины: текст до 500 символов, длинный текст до 3000.
- Значения очищаются и приводятся к типу поля: пустые отбрасываются, числа (в том числе строки с запятой вместо точки) становятся числом по модулю не больше миллиарда, для списков допустимы только объявленные варианты.
- Неизвестный ключ в значениях — ошибка; обязательное поле без значения — ошибка; обязательное поле `BOOLEAN` должно быть отмечено.
- Ошибки возвращаются как `400` с понятным сообщением, например «Поле «Размер»: недопустимый вариант».

## Снимок схемы

Поля шаблона копируются в мероприятие снимком (`events.fields`). Правка шаблона не ломает уже созданные события. Значения полей хранятся в `events.details`, свои параметры — в `events.custom_fields`, анкета — в `events.registration_fields`, сведения организации — в `events.org_details`.

## Как добавить новый формат

Новый формат — одна строка в таблице `event_templates`: `code`, название, значки, `audience` (`ANY` или `ORGANIZATION`), JSON-схемы `fields` и `registration_fields`, значения по умолчанию. Правок кода и релиза не требуется.
