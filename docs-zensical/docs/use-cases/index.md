# Use cases

Сценарии использования сгруппированы по ролям. Идентификаторы используются в [покрытии ТЗ](../business/coverage.md) и [user flows](../user-flows/index.md).

| Роль | Страница | Идентификаторы |
|------|----------|----------------|
| Пользователь | [Пользователь](user.md) | UC-U-01 … UC-U-16 |
| Организатор | [Организатор](organizer.md) | UC-O-01 … UC-O-11 |
| Администратор | [Администратор](admin.md) | UC-A-01 … UC-A-07 |

## Общие правила

- Гость видит приветственную страницу и вход; каталог, карточки, обсуждения и профили открываются после входа (по API чтение без токена доступно). Для любого действия, меняющего данные, нужен вход.
- Администратор не создаёт мероприятия, не записывается на них, не дружит и не подписывается: бэкенд отвечает `403`.
- Любая ошибка возвращается в формате `{"error": {"code", "message"}}` с осмысленным HTTP-статусом (`400`, `401`, `403`, `404`, `409`).
