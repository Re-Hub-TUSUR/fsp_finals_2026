# Use cases организатора

Организатор — автор мероприятия (пользователь) либо владелец организации. Права проверяются по принадлежности мероприятия.

| ID | Сценарий | Предусловие | Результат |
|----|----------|-------------|-----------|
| UC-O-01 | Зарегистрировать организацию | — | Организация со статусом `PENDING`; публикация заблокирована до решения администратора |
| UC-O-02 | Собрать мероприятие в конструкторе | Вход; для организации — статус `APPROVED` | Выбран шаблон, заполнены поля, вид спорта (в том числе свой), параметры, анкета участника, место и время |
| UC-O-03 | Указать сведения организатора | Мероприятие от организации | Контакты (обязательны), площадка, справка, страховка, документы, призы, программа, условия отмены, партнёры |
| UC-O-04 | Принять или отклонить заявку | Есть заявки `PENDING` | `CONFIRMED` (выдаётся билет) или `REJECTED` с комментарием; участник видит новый статус |
| UC-O-05 | Исключить подтверждённого участника | Участие `CONFIRMED` | Статус `REJECTED`, место освобождено |
| UC-O-06 | Ответить в обсуждении | Вход | Ответ помечен значком «Организатор» (ставит бэкенд) |
| UC-O-07 | Отметить участника на входе | Мероприятие организатора | Сканирование QR камерой или ввод кода вручную; статусы `SUCCESS`, `ALREADY_CHECKED_IN`, `NOT_FOUND`, `WRONG_EVENT`, `NOT_CONFIRMED` |
| UC-O-08 | Завершить мероприятие | Время окончания прошло; статус `PUBLISHED` | Мероприятие переходит в `ARCHIVED` и попадает в архив организатора и участников |
| UC-O-09 | Исправить отклонённое автопроверкой | Мероприятие `UNPUBLISHED` с причиной | Автор видит причину на форме и в «Моих событиях»; администратор может вернуть мероприятие |

## Статусы организации

`PENDING` → `APPROVED` (публикация без премодерации) либо `REJECTED` (с причиной, видна владельцу). Профиль неодобренной организации виден только владельцу и администратору.
