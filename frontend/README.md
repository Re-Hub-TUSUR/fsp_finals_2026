# Sportikus — веб-клиент

Одностраничное приложение платформы Sportikus: приветственная страница для гостей и обучающий тур, карта и каталог мероприятий, конструктор (в том числе повторяющиеся занятия), запись с подтверждением и очередью, QR-билеты и контроль входа, рекомендации и тест интересов, друзья и уведомления, профили, модерация. Приложение устанавливается на телефон как PWA. Общее описание проекта и запуск всей системы — в [корневом README](../README.md); устройство бэкенда — в [`docs/architecture.md`](../docs/architecture.md).

## Стек

* **React 19**, **TypeScript** (строгие проверки: `noUnusedLocals`, `verbatimModuleSyntax`, `erasableSyntaxOnly`), **Vite**.
* **Tailwind CSS 4** с дизайн-токенами в `src/index.css` (`@theme`): светлая и тёмная темы переключаются атрибутом `data-theme` на `<html>`.
* **React Router 7**, **axios**, **lucide-react**.
* **2GIS MapGL JS API** (`@2gis/mapgl`) — карты, метки и кластеры.
* **`qrcode`** (QR-билет рисуется на устройстве) и **`html5-qrcode`** (сканер билетов: камера и распознавание с фото).
* **PWA**: манифест и service worker в `public/`.
* **Vitest + Testing Library + jsdom** — автотесты; линтер **oxlint**.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Запросы `/api` Vite проксирует на `http://localhost:8080` (см. `vite.config.ts`), поэтому для разработки достаточно поднять бэкенд и базу:

```bash
docker compose up -d postgres redis     # из корня проекта: PostgreSQL с PostGIS и Redis (кэш карты, необязателен)
cd ../backend && mvn spring-boot:run
```

> В dev-режиме проксируется только `/api`. Загруженные фото профилей отдаются по `/uploads/...` — они доступны при запуске через Docker (nginx), но не через Vite.

Скрипты:

| Команда | Назначение |
| :--- | :--- |
| `npm run dev` | Dev-сервер с HMR (service worker в нём не регистрируется) |
| `npm run build` | Проверка типов (`tsc -b`) и production-сборка в `dist/` |
| `npm run preview` | Просмотр собранной версии на `http://localhost:4173` — здесь работает service worker |
| `npm run lint` | Проверка oxlint |
| `npm run test` | Автотесты (Vitest + Testing Library), один прогон |
| `npm run test:watch` | Автотесты в watch-режиме |

## Автотесты

Vitest + React Testing Library + jsdom (конфиг — `vitest.config.ts`, setup — `src/test/setup.ts`). Файлы `*.test.ts(x)` лежат рядом с кодом. Покрыты:

- **Чистая логика** (`src/utils/*.test.ts`): форматирование времени, цены и плюрализация, часовые пояса, геометрия (расстояние, адрес), статусы мест и очередь, погода, автопроверка, снимок списка мероприятий, камера сканера (определение защищённой страницы, классификация ошибок, повторные сканы), безопасный адрес возврата после входа (`redirect`).
- **Конструктор форм**: `FieldInput`, `TagInput`, `CustomFieldsEditor`, `QuestionsEditor`.
- **Карточки и запись**: `EventCard`, `MapEventCard`, `EventBits`, `ParticipationBadge`, `JoinDialog`, `RouteButton`.
- **Тест интересов** `InterestQuiz` (6 шагов): подбор видов спорта по возрасту и типу досуга, шаг уровня, сохранение домашней точки и бюджета при повторном прохождении, ошибка сохранения, «Повторить» при сбое загрузки справочников.
- **Обучающий тур** `OnboardingTour`: запуск и пропуск, шаги, учебная встреча на карте (нажатие на метку и «Подать заявку» ведут тур дальше, после тура встреча исчезает), пример заявки и QR-билета, финальное приглашение в тест.
- **Учебная встреча в карточке** `MapEventCard`: «Подать заявку» не обращается к серверу.
- **Панель администратора** `AdminPage`: поиск по организациям, мероприятиям и комментариям, переходы на страницу организации и организатора.
- **Устойчивость к сбоям**: `ErrorNotice` (блок ошибки с «Повторить»), `CancelParticipationDialog` (подтверждение отмены участия).
- **Сканер билетов** `CheckInScannerModal`: HTTPS-проверка, ошибки камеры, один скан — одна отметка, фото с QR, фонарик, счётчик отмеченных, ручной ввод.
- **Уведомления и PWA**: `NotificationBell`, баннеры установки и «нет сети», регистрация service worker, очистка офлайн-данных.
- **Регрессии**: `CreateEventPage` — «белый экран при выборе свободного входа» (sr-only radio без `position: relative` на обёртке).

Тесты, трогающие 2GIS (`LocationPicker`, `html5-qrcode`) или сеть (`../api`, `AuthContext`), мокают эти модули — SDK карты и камера в jsdom недоступны.

## Переменные окружения

Все переменные начинаются с `VITE_` и **встраиваются в бандл при сборке**. Пример — [`../.env.example`](../.env.example).

| Переменная | Назначение |
| :--- | :--- |
| `VITE_2GIS_KEY` | Ключ 2GIS MapGL JS API ([platform.2gis.ru](https://platform.2gis.ru)). Без ключа вместо карты показывается заглушка, остальной интерфейс работает |
| `VITE_2GIS_STYLE_ID` | ID своего стиля карты из [редактора стилей](https://styles.2gis.com); пусто — стандартный стиль |
| `VITE_2GIS_STYLE_ID_DARK` | Тёмный стиль для тёмной темы; пусто — карта остаётся светлой |
| `VITE_API_URL` | Адрес API; по умолчанию `/api/v1` (nginx в Docker, прокси Vite в dev) |

Ключ и стили `VITE_2GIS_*` читаются из `.env` в **корне проекта** (рядом с `docker-compose.yml`) или из `frontend/.env`; второй приоритетнее. В Docker они передаются как build-аргументы, поэтому после изменения нужна пересборка: `docker compose up --build -d`.

Прогноз погоды (Open-Meteo) и часть фото обложек (Unsplash) подгружаются из внешних сервисов напрямую из браузера и ключей не требуют.

## Маршруты

| Путь | Страница | Доступ |
| :--- | :--- | :--- |
| `/welcome` | Приветственная страница: цифры платформы, ближайшие встречи, вход и регистрация. Всё остальное, кроме `/auth`, гость видит только через неё (`/welcome?next=…` возвращает после входа) | гость (вошедшего перенаправляет на `/`) |
| `/` , `/events` | Главная: карта 2GIS и список, поиск, фильтры; при разрешённой геолокации — расстояние до мероприятий. Выбор города — значок локации в шапке. При первом входе пользователя запускается обучающий тур (`/?tour=1` — запустить вручную) | вход |
| `/events/:id` | Карточка мероприятия: запись, заявка или очередь, QR-билет, обсуждение, погода, маршрут, пригласить друзей, «Поделиться», экспорт в календарь, «Завершить событие» и контроль входа (организатор) | вход (гость по ссылке попадает на `/welcome`, после входа возвращается сюда) |
| `/events/new` | Конструктор мероприятия, в том числе «Повторять событие» (интервал 1–365 дней); после отправки — автопроверка (несколько секунд) и сообщение, если мероприятие не прошло | пользователь или одобренная организация |
| `/events/:id/manage` | Заявки и участники, решения организатора, «Экспорт в CSV», сканер QR | организатор мероприятия |
| `/my` | Личный кабинет: «Я участвую» (билеты, очередь, отмена с подтверждением), «Я организую», «Архив» | вход |
| `/recommended` | «Рекомендовано для вас»: подборка с причинами и «Не интересно», тест интересов; пункт «Для вас» в верхнем меню и нижней панели | вход (не для администратора) |
| `/notifications` | Все уведомления; колокольчик в шапке показывает непрочитанные | вход |
| `/auth` | Вход и регистрация (пользователь или организация), показ пароля; `?mode=user\|organization` открывает нужную вкладку, `?next=` задаёт возврат | публично |
| `/profile`, `/profiles/:type/:id` | Свой профиль и публичные профили (`type` — `users` или `organizations`). В собственном профиле: «Мои интересы», тест и «Обучение по сайту», вкладки «Друзья», «Подписки», «Достижения»; в профиле организации — «Подписаться» | публично (редактирование — владелец) |
| `/admin` | Модерация: организации, мероприятия (пометка ⚠ после автопроверки, «Проверено»), комментарии; поиск на каждой вкладке, ссылки на страницу организации и организатора | администратор |

## Ключевые решения

* **Аутентификация.** JWT хранится в `localStorage` и добавляется к запросам перехватчиком axios. Панель «Демо-режим» входит под сидовыми аккаунтами через тот же `POST /auth/login` — клиент не подменяет роль, а все права проверяет бэкенд. При старте без сети клиент не выходит из аккаунта: токен сбрасывается только после ответа сервера `401`.
* **Конструктор на данных.** Форма создания строится из описаний полей шаблона (`FieldDef`): `FieldInput` рисует поле нужного типа, поэтому новые форматы мероприятий не требуют изменений клиента. Тот же компонент рисует анкету участника в `JoinDialog`.
* **Каталог по области карты.** Главная запрашивает события для видимой области (центр и радиус до 300 км), а не весь список — иначе на масштабе страны не обойтись. Бэкенд кэширует такие списки в Redis на 60 секунд, поэтому число занятых мест в списке может отставать; карточка мероприятия всегда точная.
* **Время площадки.** Время показывается в часовом поясе мероприятия и подписывается «местное», если оно отличается от пояса устройства; при создании введённое время трактуется как местное время площадки (`utils/format.ts`).
* **Карты 2GIS.** SDK подгружается один раз; при смене темы карта пересоздаётся со стилем нужной темы, положение камеры сохраняется. Ошибки загрузки и отсутствие ключа показываются заглушкой `MapFallback`.
* **Тема.** Цвета заданы токенами (`bg-page`, `text-ink`, `brand` …), выбор темы запоминается в `localStorage`.
* **Сканер билетов.** Камера требует `https://` или `localhost`: `utils/camera.ts` заранее проверяет `isSecureContext` и объясняет причину, если камеры нет. Сканер выводится порталом на весь экран; контейнер видоискателя показывается до запуска камеры (иначе видео получает ширину 0), а повтор того же кода в течение 15 секунд игнорируется. Есть фонарик (если поддерживает устройство), «Фото QR-кода» работает и без HTTPS. Поверх камеры цвета заданы явно (`text-[#fff]`): в тёмной теме токен `--color-white` инвертируется.
* **PWA и офлайн.** Service worker кэширует оболочку приложения и ответы личного кабинета (`/me/participations`, `/me/events`, `/auth/me`, `/me/preferences`); каталог и запись всегда идут в сеть. Сохранённые данные удаляются при выходе и смене аккаунта. Service worker регистрируется только в production-сборке и только на доверенном HTTPS — на самоподписанном сертификате браузер его не примет.
* **Очередь на места.** Статус `WAITLISTED` показывается как «В очереди»; когда место освободилось, кнопка меняется на «Занять место» и отправляет запись без анкеты (`useEventJoin`).
* **Гость и возврат.** `AppShell` в `App.tsx` пускает гостя только на `GUEST_PATHS` (`/welcome`, `/auth`), остальное перенаправляет на `/welcome?next=…`. Пока проверяется сохранённый токен, показывается экран загрузки (с пояснением, если сервер отвечает дольше 4 секунд); `?next=` проходит `safeNext`. Если токен есть, но сервер недоступен, пользователь остаётся в приложении (офлайн-режим), а не выбрасывается на лендинг.
* **Сбои сети.** У axios таймаут 20 секунд (у `/auth/me` — 8), `errorMessage` отличает «нет связи» и «сервер слишком долго не отвечает». Страницы, которые не загрузили данные, показывают `ErrorNotice` с кнопкой «Повторить»; тест интересов повторяет загрузку справочников. Отмена участия просит подтверждение.
* **Обучающий тур.** `OnboardingTour` ищет элементы по атрибутам `data-tour` (отдельные варианты `-mobile` для нижней панели), подсвечивает их и подбирает положение подсказки под ширину экрана. Шаги 6–9 — учебная запись: `utils/tourDemo.ts` включает учебную встречу (id `-1`), главная ставит её метку рядом с центром карты (поверх кластеров, в стиле выбранной), клик по метке и «Подать заявку» в обычной карточке сообщают туру, что пользователь сделал шаг. На этих шагах вокруг подсвеченного элемента лежат четыре «заслонки», а сам элемент кликается насквозь. `useEventJoin`, «Подробнее» и ссылка карточки для учебной встречи не ходят на сервер. Дальше — пример заявки и QR-билета (`TourDemoStand`); на финале и при пропуске встреча убирается. Запускается после регистрации (`sessionStorage`), при первом входе `ROLE_USER` на главной (`localStorage`, ключ на пользователя), по `?tour=1` и событием `start-sportikus-tour` из профиля.
* **Шапка.** Выбор города — значок со стрелкой без подписи (название — в подсказке), на ширине до 1024 px вкладки сжимаются до иконок, а имя пользователя показывается с 1536 px.

## Линтер

Используется [oxlint](https://oxc.rs/docs/guide/usage/linter) с правилами `react/rules-of-hooks` (ошибка) и `react/only-export-components` (предупреждение) — см. `.oxlintrc.json`. Для типо-зависимых правил можно установить `oxlint-tsgolint` и добавить в конфиг `"options": { "typeAware": true }`.
