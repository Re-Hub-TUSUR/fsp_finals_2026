# 🏆 Sportikus — Платформа спортивных активностей

> **Финал Чемпионата России по продуктовому программированию (ФСП, кейс Столото)**
> **Миссия:** от идеи потренироваться к конкретной компании за 2 клика — в любом городе страны.

Sportikus помогает найти и организовать спортивное (и не только) мероприятие рядом: карта и каталог по всей России, гибкий конструктор мероприятий, запись по заявке с подтверждением организатора и очередью на места, электронные QR-билеты с отметкой на входе, обсуждение под событием, друзья и приглашения, напоминания о мероприятиях, повторяющиеся занятия, организации с модерацией, персональные рекомендации с понятными причинами, приветственная страница для гостей, обучающий тур для новичков и установка как приложения (PWA).

## ✨ Возможности

| Область | Что умеет платформа |
| :--- | :--- |
| 👋 **Знакомство** | Приветственная страница для гостя (`/welcome`) с живыми цифрами платформы и ближайшими встречами; интерактивный обучающий тур по сайту для нового пользователя (на телефоне и в вебе) и тест интересов в конце |
| 🗺️ **Карта и каталог** | Карта 2GIS с метками мероприятий (время до старта, свободные места), список, поиск, фильтры: виды спорта (несколько), уровень, режим записи, время, расстояние от вас (если разрешена геолокация), «только бесплатные». Каталог загружается для видимой области карты |
| 🧩 **Конструктор мероприятий** | Готовые шаблоны с настраиваемыми полями, свой вид спорта, свои параметры, анкета для участников; для организаций — блок сведений организатора; **повторение**: следующее занятие создаётся при завершении текущего |
| 👤 **Мероприятия от пользователя и организации** | Пользователь публикует от своего имени, организация — от имени организации после одобрения администратором |
| ✅ **Участие с подтверждением** | Режим «по заявке» (организатор принимает или отклоняет) и «свободный вход»; отмена, исключение, лимит мест; **очередь**, когда мест нет: освободившееся место получает первый откликнувшийся |
| 🎫 **QR-билеты и вход** | У подтверждённого участника — уникальный билет `SPT-XXXXXXXX` с QR-кодом (работает офлайн); организатор сканирует QR камерой на весь экран (с фонариком), по фото или вводит код — вход по билету одноразовый, виден счётчик отмеченных |
| 🏁 **Архив и повторы** | Организатор завершает прошедшее мероприятие — оно уходит в архив организатора и участников и приносит достижения; у повторяющегося сразу появляется следующее занятие. Список участников выгружается в CSV |
| 💬 **Обсуждение под событием** | Вопросы участников и ответы организатора со значком «Организатор», автообновление каждые 8 секунд, скрытие сообщений |
| 🎯 **Рекомендации** | Пункт «Для вас» в меню (`/recommended`): подборка по интересам, месту, времени и истории с причинами («Вы интересуетесь: Бег», «1,4 км от вас»), «Не интересно». Интересы задаются в профиле или за минуту в тесте «Компас интересов» (6 шагов, учитывает возраст и уровень) |
| 🤝 **Друзья и приглашения** | Заявки в друзья, поиск по e-mail, «Идут друзья» на карточке, приглашение друзей на мероприятие, «Поделиться» (ссылка, VK, системное меню телефона) |
| 🔔 **Уведомления** | Колокольчик в шапке и страница `/notifications`: решения организатора, приглашения, заявки в друзья, освободившиеся места из очереди, **напоминание за сутки до начала** мероприятия |
| ⭐ **Подписки и достижения** | Подписка на организации; 30 достижений за участие, дружбу, организацию и разные виды спорта с уведомлением о новом |
| 🌤️ **Погода и маршрут** | Прогноз погоды на время мероприятия (Open-Meteo, ближайшие ~15 дней); кнопка «Маршрут» с выбором 2GIS, Яндекс Карт или Google Maps |
| 🔐 **Аккаунты** | Регистрация пользователя и организации (ИНН/ОГРН/КПП), вход по JWT, профили с фото и логотипом, интересы пользователя |
| 🤖 **Автопроверка мероприятий** | Фильтр запрещённых тем (политика, алкоголь, дискриминация и др.) и при сомнении — ИИ через RouterAI: за несколько секунд после создания мероприятие публикуется или отклоняется с причиной; сомнительное помечается ⚠ для администратора |
| 🛡️ **Модерация** | Одобрение/отклонение организаций с причиной, снятие мероприятий с публикации и возврат, скрытие комментариев, разбор мероприятий с пометкой ⚠ |
| 🌍 **Вся страна** | Геопоиск PostGIS, 44 города со справочником часовых поясов, время показывается по местному времени площадки |
| 🌗 **Интерфейс** | Светлая и тёмная темы, адаптивная вёрстка с нижней навигацией на телефоне, экспорт события в календарь (`.ics`); при сбое сети — понятное сообщение с кнопкой «Повторить», подтверждение отмены участия, показ пароля при вводе |

## 🛠️ Стек технологий

* **Backend:** Java 21, Spring Boot 3.3, Spring Data JPA, Spring Security (JWT), Flyway, Springdoc OpenAPI (Swagger UI).
* **База данных:** PostgreSQL 16 + **PostGIS** (геопоиск, материализованные представления, секционированный журнал).
* **Кэш:** Redis 7 — кэш списка мероприятий для карты (необязателен: без него запросы идут в БД).
* **Frontend:** React 19, Vite, TypeScript, Tailwind CSS 4, React Router, карты **2GIS MapGL JS API**, Lucide Icons; `qrcode` и `html5-qrcode` для билетов; service worker для PWA.
* **Тесты:** JUnit 5 + AssertJ (backend), Vitest + Testing Library (frontend).
* **DevOps:** Docker, Docker Compose, Nginx.

## 🚀 Быстрый запуск

Нужен запущенный **Docker Desktop**. В корне проекта:

```bash
# 1. (необязательно) ключ карт 2GIS — без него приложение работает, но вместо карты будет заглушка
cp .env.example .env
#    откройте .env и впишите VITE_2GIS_KEY (получить: https://platform.2gis.ru)

# 2. Сборка и запуск базы, бэкенда и веб-клиента
docker compose up --build -d

# 3. Проверка состояния
docker compose ps
```

> Ключ 2GIS встраивается в фронтенд **при сборке**, поэтому после его изменения нужна пересборка: `docker compose up --build -d`.

### ♻️ Сброс данных

Схема и демо-данные создаются миграциями при старте. После обновления схемы или демо-данных пересоздайте базу и загрузки:

```bash
docker compose down -v && docker compose up --build -d
```

Данные хранятся в двух volume: `postgres_data` (база) и `profile_uploads` (фото профилей и логотипы). Обычный `docker compose up -d --build` данные не стирает; `down -v` удаляет их безвозвратно.

## 🧑‍💻 Разработка без Docker

Для бэкенда нужны **Java 21**, **Maven 3.9+** и PostgreSQL **с расширением PostGIS** — обычный PostgreSQL не подойдёт (миграция выполняет `CREATE EXTENSION postgis`). Проще всего поднять только базу (и необязательный Redis для кэша карты) из compose:

```bash
docker compose up -d postgres redis
```

```bash
# Backend (http://localhost:8080)
cd backend
mvn spring-boot:run
```

```bash
# Frontend (http://localhost:5173)
cd frontend
npm install
npm run dev
```

Vite проксирует запросы `/api` на `http://localhost:8080`. Ключ 2GIS берётся из `.env` в корне проекта или из `frontend/.env` (`frontend/.env` приоритетнее). Подробнее — в [`frontend/README.md`](frontend/README.md).

## 🧩 Конструктор мероприятий

Создание мероприятия (`/events/new`) собирается из блоков, а формат мероприятия описывается **данными, а не кодом**:

1. **Шаблон** (`GET /api/v1/templates`): «Тренировка», «Игра / матч», «Турнир», «Забег» (только для организаций), «Интеллектуальная игра», «Поход», «Мастер-класс» (не спорт) и «Свободный формат». Шаблон задаёт значения по умолчанию, набор дополнительных полей (`TEXT`, `TEXTAREA`, `NUMBER`, `SELECT`, `MULTISELECT`, `BOOLEAN`) и вопросы участнику. Новый формат — это одна строка в таблице `event_templates` (JSON-схема полей), без правок кода.
2. **Вид спорта:** выбор из списка или «+ Свой вид спорта» — название нормализуется в slug (`Воркаут` → `vorkaut`) и сразу попадает в общий каталог и фильтры.
3. **Свои параметры:** произвольные пары «название — значение» поверх шаблона.
4. **Анкета участника:** организатор сам добавляет вопросы (текст, число, выбор, да/нет), на которые отвечает подающий заявку. Поля шаблона копируются в мероприятие снимком, поэтому правки шаблона не ломают уже созданные события.
5. **Данные организатора** (только для организаций, контакты обязательны): контактное лицо, телефон/e-mail, сайт или регламент, площадка, медицинская справка и страховка, список документов, призы, программа, инфраструктура, условия отмены, партнёры. Если заданы требования, участник подтверждает ознакомление при подаче заявки.
6. **Место и время:** точка выбирается кликом по карте; время вводится **по местному времени площадки** (город и часовой пояс определяются по точке).

Публикует мероприятие пользователь — от своего имени; организатор — от имени организации, **только после одобрения** администратором (иначе `403`).

## 👋 Знакомство с платформой: лендинг и обучение

**Гость.** Без входа открывается только приветственная страница `/welcome` и вход `/auth`. Любой другой адрес (например, ссылка на мероприятие, которой поделился друг) ведёт гостя на `/welcome?next=…`; после входа или регистрации он возвращается туда, куда шёл. Адрес возврата проверяется (`safeNext`): принимаются только внутренние пути, поэтому `?next=//evil.com` отбрасывается. Страница показывает цифры платформы из публичного `GET /api/v1/public/stats` (предстоящие мероприятия, участники, виды спорта, организации) и ближайшие встречи; без цифр она тоже работает. Картинки лендинга лежат в `frontend/public/landing/` в двух размерах (`-m` для телефона), nginx отдаёт их с кэшем на неделю и сжимает JS/CSS (gzip).

**Обучающий тур** (`OnboardingTour`). Подсвечивает элементы интерфейса и по шагам объясняет: персональные рекомендации, карта и лента, фильтры и радиус, поиск и город, организация событий и QR-билеты; в финале предлагает пройти тест интересов. На телефоне подсказки адаптируются под экран. Тур запускается сам после регистрации пользователя и при первом входе пользователя с ролью `ROLE_USER` на главной (отметка о прохождении хранится в браузере отдельно для каждого аккаунта), его можно пропустить, а потом повторить кнопкой «Обучение по сайту» в профиле или ссылкой `/?tour=1`.

**Тест «Компас интересов»** — шесть шагов (подробнее — в разделе [Рекомендации](#-рекомендации)): год рождения, тип досуга, удобное время, виды спорта, уровень, город и расстояние.

**Сбои сети.** При старте приложение проверяет сохранённый вход: если сервер отвечает больше нескольких секунд, показывается экран загрузки с пояснением, а не пустота (таймаут запроса — 8 секунд для проверки входа и 20 для остальных). Если страница не смогла загрузить данные, она показывает ошибку с кнопкой «Повторить».

## ✅ Участие с подтверждением

| Режим | Что происходит при записи |
| :--- | :--- |
| `APPROVAL` (по умолчанию) | Создаётся заявка `PENDING` с анкетой и сообщением. Место занимает только подтверждённая заявка: организатор принимает (`CONFIRMED`) или отклоняет (`REJECTED`, с комментарием) на `/events/:id/manage` |
| `OPEN` | Запись подтверждается сразу (`CONFIRMED`) |
| Мест нет | Участник встаёт в очередь (`WAITLISTED`) и места не занимает |

Перед отправкой участник видит диалог подтверждения: время, место, цену, требования и анкету. Дальше — состояния «Заявка на рассмотрении» → «Вы участвуете» / «Заявка отклонена». Участник может отозвать заявку или отменить участие (перед этим приложение просит подтверждение — на странице мероприятия и в «Моих событиях») и записаться снова; организатор может исключить подтверждённого участника. Места выдаются под блокировкой строки мероприятия — последнее место нельзя занять дважды. Проверяются: собственное мероприятие, снятие с публикации, завершение, закрытая регистрация, повторные заявки, возрастные ограничения (по году рождения из профиля).

**Очередь.** Когда подтверждённый участник отменяет запись или организатор его исключает, все ожидающие получают уведомление «Освободилось место», а место достаётся первому, кто откликнется (повторный «Записаться»). Остальным приходит «Место заняли». Таймеров нет: неактивный человек очередь не задерживает. Заявку из очереди организатор подтвердить не может — место занимает сам участник.

```
OPEN       join ───────────────────────────────▶ CONFIRMED
APPROVAL   join ─▶ PENDING ─ организатор ─────▶ CONFIRMED | REJECTED
мест нет   join ─▶ WAITLISTED ─ место освободилось, откликнулся первым ─▶ CONFIRMED | PENDING
CONFIRMED ─ организатор ─▶ REJECTED (исключение)    PENDING | CONFIRMED | WAITLISTED ─ участник ─▶ CANCELLED
```

## 🎫 Билеты и вход на мероприятие

* **Билет** выдаётся при подтверждении участия: код `SPT-XXXXXXXX` (8 символов случайного UUID, уникален). Участник открывает его кнопкой «Показать QR-билет» на странице мероприятия или в «Моих событиях»; QR строится на устройстве, поэтому билет доступен и без сети, если страницу открывали раньше.
* **Контроль входа** — у организатора на странице мероприятия кнопка «Контроль входа (Сканер QR)», а на `/events/:id/manage` — «Сканировать QR / Ввести код». Сканер открывается на весь экран: камера с рамкой наведения, кнопки «Фото QR-кода» (системная камера телефона, работает и без HTTPS), включения камеры и **фонарика** (если устройство его поддерживает). Внизу — результат последней отметки (имя и фото участника, признак платного входа), счётчик «Отмечено на мероприятии» (отмечено / подтверждено) и ввод кода билета вручную; есть список подтверждённых с кнопкой «Отметить вход».
* `POST /api/v1/events/{id}/checkin` отвечает одним из статусов: `SUCCESS` (допущен), `ALREADY_CHECKED_IN` (билет уже использован, со временем первой отметки), `WRONG_EVENT`, `NOT_CONFIRMED`, `NOT_FOUND`. В ответе есть имя и аватар участника для сверки, а также признак платного входа и цена.
* Код билета **постоянный**, а вход по нему **одноразовый**. Пересланный скриншот QR пропустит того, кто придёт первым, — поэтому при сканировании показываются имя и фото участника. Динамический QR (код, меняющийся каждые ~30 секунд) не реализован.
* Пока QR в кадре, камера считывает его много раз в секунду: повтор того же кода в течение 15 секунд игнорируется, поэтому успешная отметка не сменяется «Билет уже использован».

## 🏁 Завершение, повторы и архив

Организатор нажимает «Завершить событие» на странице мероприятия — только после времени окончания (`POST /api/v1/events/{id}/complete`). Мероприятие получает статус `ARCHIVED`, пропадает из каталога, карты и рекомендаций и остаётся во вкладке «Архив» в «Моих событиях» у организатора и подтверждённых участников. Завершённые мероприятия учитываются в достижениях.

**Повторяющиеся мероприятия.** В конструкторе («Повторять событие») задаётся интервал от 1 до 365 дней; в API это `recurrenceRule` (`NONE`, `WEEKLY` — раз в 7 дней, `CUSTOM` — со своим `recurrenceIntervalDays`). Следующее занятие появляется в момент завершения текущего: копия с теми же описанием, местом, ценой, лимитом мест, анкетой и результатом автопроверки, дата сдвинута на интервал **по местному времени площадки** и не может оказаться в прошлом. Участники не переносятся — на новое занятие записываются заново. Ссылка на следующее занятие — `nextOccurrenceId` в карточке завершённого; занятия одной серии связаны общим `recurrence_series_id`.

**Экспорт участников.** На `/events/:id/manage` кнопка «Экспорт в CSV» (для Excel) выгружает статусы, билеты, явку и ответы анкеты; значения экранируются от формульных инъекций. Тот же файл отдаёт `GET /api/v1/events/{id}/participations/export`.

## 🎯 Рекомендации

Страница **«Рекомендовано для вас»** (`/recommended`, пункт **«Для вас»** в верхнем меню и в нижней панели на телефоне; нужен вход) подбирает мероприятия по интересам, месту, времени и истории пользователя. Каждая карточка показывает причины, а кнопка «Не интересно» скрывает событие и понижает похожие (с возможностью отмены).

**Как это работает** (подробно — в [`docs/architecture.md`](docs/architecture.md#6-рекомендательная-система)):

* **Без Elasticsearch.** Всё считается внутри бэкенда на данных PostgreSQL + PostGIS: данные всегда свежие (свободные места, статус, заявки), нет синхронизации индекса.
* **Кандидаты из четырёх источников** (интересы, популярное рядом, знакомые организаторы, ближайшие по времени) — каждый с лимитом, поэтому даже плотный город не перегружает расчёт.
* **Прозрачное ранжирование** (`weighted-v1`): интерес, расстояние, накопленный интерес, срочность, уровень, популярность, организатор, удобное время — по местному времени площадки; штраф за отвергнутое; не больше двух событий одного вида подряд.
* **Сигналы поведения** с затуханием (период полураспада 90 дней) и «похожие виды спорта» по поведению других пользователей.
* **Холодный старт:** без интересов показывается популярное рядом; без местоположения — предложение указать город или разрешить геолокацию.
* **Точка поиска:** геолокация устройства → домашняя точка → центр домашнего города.
* **Кэш** выдачи на 2 минуты со сбросом при действиях пользователя; **фоновые задачи** (популярность каждые 5 минут, ночной пересчёт сигналов) безопасны при нескольких экземплярах бэкенда.
* **Журнал** показов, кликов, отказов и записей (`recommendation_log`) — основа для метрик и будущей обученной модели.

Интересы задаются через `PUT /api/v1/me/preferences` (вид спорта, город, радиус, уровень, удобное время, бюджет, год рождения; запрос заменяет сохранённые значения целиком). Возраст используется как жёсткий фильтр по ограничениям мероприятия (`minAge`/`maxAge`), а не как вес ранжирования. В интерфейсе их собирают тремя способами, и все они пишут в одни и те же предпочтения:

* **Тест «Компас интересов»** — шесть шагов: год рождения, тип досуга («Активный», «Спокойный», «В компании», «Новые впечатления»), удобное время, виды спорта, уровень (новичок, любитель, опытный, «Не важно») и город с расстоянием (с переключателем «Только бесплатные»). На шаге видов спорта наверху показываются до 8 подходящих по возрасту и типу досуга («Возможно, вам понравится»), остальные ниже. Тест запускается из обучающего тура, кнопкой «Пройти тест» в профиле и на странице рекомендаций; «Смотреть рекомендации» в конце ведёт на `/recommended`. Если справочники не загрузились, тест предлагает «Повторить». При повторном прохождении сохраняются домашняя точка и бюджет, а ответы на всех шагах подставляются заново.
* **Блок «Мои интересы»** в личном профиле (`/profile`) — подробная форма.
* Кнопка «Мои интересы» на странице рекомендаций — та же форма в окне.

Регистрация интересы не запрашивает: до первого заполнения пользователь видит популярное рядом и приглашение указать интересы.

Настройка без пересборки — `application.yml`:

```yaml
recommendations:
  default-radius-km: 25        # радиус поиска, если пользователь не задал свой
  horizon-days: 30             # рекомендуем события на ближайшие N дней
  candidates-per-source: 300   # лимит кандидатов с одного источника
  cache-ttl: PT2M
  max-same-sport-in-row: 2
  affinity-half-life-days: 90
  weights: { interest: 0.35, distance: 0.20, affinity: 0.15, urgency: 0.10,
             skill: 0.08, social: 0.07, organizer: 0.05, time: 0.05, dislike-penalty: 0.30 }
  jobs: { enabled: true, popularity-refresh: PT5M, nightly-cron: "0 30 3 * * *" }
```

## 👥 Аккаунты, организации и профили

* **Регистрация** (`/auth`): пользователь — имя, фамилия, e-mail, пароль (8–72 символа), доступ сразу; организация — название, ИНН (10/12 цифр), ОГРН (13/15), КПП (9), e-mail, пароль. Организация создаётся в статусе `PENDING`: публиковать мероприятия можно только после одобрения администратором, отказ приходит с причиной. ИНН и ОГРН уникальны.
* **Профили** (`/profile`, `/profiles/users/:id`, `/profiles/organizations/:id`): публичная страница с текущими мероприятиями; владелец редактирует имя, описание организации и загружает фото или логотип (JPG, PNG, WebP до 5 МБ). Профиль неодобренной организации виден только владельцу и администратору.
* **Интересы** (в собственном профиле пользователя): виды спорта, город, радиус поиска, уровень, удобное время, бюджет, год рождения. Сводка и форма редактирования; от них зависит страница «Для вас».
* **Личный кабинет** (`/my`): «Я участвую» (заявки, статусы, билеты и очередь), «Я организую» (мероприятия и число заявок в ожидании) и «Архив» завершённых мероприятий.
* **Модерация** (`/admin`): организации (одобрить / отклонить с причиной), мероприятия (снять с публикации с причиной / вернуть; фильтры «⚠ Требуют внимания» и «Отклонены автопроверкой», кнопка «Проверено») и комментарии (скрыть). На каждой вкладке есть поиск (организации — по названию, владельцу и e-mail; мероприятия — по названию, организатору, виду спорта и городу; комментарии — по тексту, автору и мероприятию), а название организации и имя организатора ведут на их страницы: оттуда видны размещённые мероприятия.

## 🤝 Друзья, подписки, достижения и уведомления

* **Друзья.** Заявка отправляется с профиля пользователя или после поиска по точному e-mail (вкладка «Друзья» в профиле); получатель принимает или отклоняет. На пару пользователей — одна запись, нельзя дружить с собой и с администратором. Друзья, которые идут на мероприятие, показываются на карточке («Идут друзья»).
* **Приглашения и «Поделиться».** На странице мероприятия кнопка «Позвать друзей» открывает список друзей: отмеченным приходит уведомление «… приглашает вас на мероприятие» со ссылкой на событие и необязательным сообщением (до 300 символов). Друзья, которых вы уже звали на это мероприятие, и те, кто уже записан, подал заявку или стоит в очереди, помечены и повторно не получают приглашение. Звать можно, пока мероприятие опубликовано и запись открыта. Поделиться мероприятием можно ссылкой, во ВКонтакте или через системное меню телефона.
* **Подписки.** Пользователь подписывается на одобренные организации (не на свою) в профиле организации; список — на вкладке «Подписки» в своём профиле.
* **Достижения.** 30 достижений в профиле (вкладка «Достижения»): участие в мероприятиях, бег и командные виды, друзья, созданные и завершённые мероприятия, разные виды спорта и «достижения за достижения». Когда пользователь получает новое, показывается всплывающая карточка.
* **Уведомления.** Колокольчик в шапке (опрос каждые 20 секунд) и страница `/notifications`: решение организатора по заявке, приглашение друга, заявка в друзья и её принятие, освободившееся и занятое место в очереди, **напоминание за сутки**. Напоминание создаёт фоновая задача раз в 5 минут (`notifications.reminders.fixed-delay`, по умолчанию `PT5M`) для каждого подтверждённого участника опубликованного мероприятия, которое начнётся в ближайшие 24 часа; уникальный индекс гарантирует одно напоминание на пару «участник + мероприятие», в том числе при нескольких экземплярах бэкенда. Клик по уведомлению ведёт на нужную страницу; можно отметить прочитанным одно или все.

Администратор в дружбе, подписках и приглашениях не участвует.

## 💬 Обсуждение под событием

На странице каждого мероприятия есть блок «Обсуждение и вопросы» — здесь участники уточняют условия, а организатор отвечает.

* **Читать** обсуждение можно без входа, **писать** — после входа (до 2000 символов; `Enter` — отправить, `Shift+Enter` — новая строка).
* Сообщения организатора мероприятия (автор события или владелец организации) помечаются значком **«Организатор»** — ставит бэкенд, а не клиент.
* Обновляется автоматически (опрос каждые 8 секунд).
* **Скрыть сообщение** может администратор, автор сообщения и организатор мероприятия. Скрытие мягкое: запись остаётся в БД, обычные пользователи видят «Сообщение скрыто модератором», настоящий текст — только администратор.
* Администратор видит все комментарии платформы с названиями мероприятий на вкладке «Комментарии» в `/admin`.

## 🤖 Автопроверка мероприятий

Каждое новое мероприятие проверяется автоматически — для автора это несколько секунд после нажатия «Опубликовать» (кнопка показывает «Публикуем и проверяем…»).

```
создание ─▶ фильтр запрещённых тем ─┬─ ничего не нашёл ──────────▶ опубликовано сразу
                                     └─ сомнение ─▶ проверка ИИ ─┬─ отклонено ─▶ не опубликовано, автор видит причину
                                                                 ├─ одобрено  ─▶ опубликовано с пометкой ⚠ для администратора
                                                                 └─ ИИ недоступен ─▶ опубликовано с пометкой ⚠ («нужна ручная проверка»)
```

1. **Фильтр запрещённых тем** (`BannedWordFilter`) ищет по словарю политику, алкоголь, табак и вейпы, наркотики и допинг, азартные игры и ставки, дискриминацию и оскорбления, насилие и экстремизм, контент 18+, финансовые схемы и спам, нецензурную лексику. Проверяются все текстовые поля: название, описание, вид спорта, параметры шаблона, свои поля, вопросы участникам, сведения организации, адрес. Обходы вроде «вoдкa» с латинскими буквами, «в0дка», «в.о.д.к.а» и «в о д к а» тоже ловятся. Фильтр не выносит приговор — он только поднимает сомнение. Кроме того, всегда проверяются ИИ мероприятия со **своим видом спорта** и в категории **«Другое»**: словарь не может оценить их тематику.
2. **Проверка ИИ** (`RouterAiModerationClient`) — запрос к [RouterAI](https://routerai.ru) (OpenAI-совместимый шлюз), модель по умолчанию **`google/gemini-2.5-flash-lite`**: быстрая (без «размышлений»), недорогая — порядка сотых долей рубля за проверку — и хорошо понимает русский. Модель решает, относится ли мероприятие к спорту, активности или ЗОЖ и нет ли нарушений; упоминание в запрещающем смысле («без алкоголя») не считается нарушением. Ответ — строго JSON с решением и причиной для автора. Текст мероприятия передаётся как данные, а не инструкции. Таймаут — 8 секунд.
3. **Итог.** Пока идёт проверка, мероприятие скрыто (статус `MODERATION`) и нигде не показывается. Отклонённое ИИ получает статус `UNPUBLISHED` с причиной «Не прошло автоматическую проверку: …» — автор видит её сразу на форме и в «Моих событиях». Одобренное ИИ публикуется, но в `/admin` → «Мероприятия» помечается знаком **⚠** с объяснением модели и найденными словами; администратор нажимает «Проверено» или снимает мероприятие с публикации. Ошибочно отклонённое можно вернуть кнопкой «Вернуть». Если ИИ недоступен (нет ключа, таймаут), добросовестный автор не ждёт — мероприятие публикуется с пометкой ⚠ «нужна ручная проверка».

Проверка ИИ выполняется вне транзакции, поэтому БД во время ожидания не блокируется. Если бэкенд перезапустился посреди проверки, фоновая задача доделает её в течение минуты.

Настройки — `application.yml`, секция `moderation`: выключатель всей проверки (`MODERATION_ENABLED`), ключ (`ROUTERAI_API_KEY`), модель (`MODERATION_LLM_MODEL`), таймаут, список видов спорта для обязательной проверки. Модель можно заменить любой из [каталога RouterAI](https://routerai.ru/models) без изменения кода, например на `deepseek/deepseek-v4.1-flash`.

## 📲 PWA, HTTPS и камера

Sportikus устанавливается на главный экран как приложение: манифест (`frontend/public/manifest.webmanifest`), иконки, ярлыки «Мои события», «Для вас», «Создать» и service worker (`frontend/public/sw.js`). Баннер установки предлагает «Установить» в Chrome/Edge и подсказывает «Поделиться → На экран „Домой“» на iPhone.

**Что работает без сети** (после первого открытия): оболочка приложения и личные данные «Моих событий» — заявки и QR-билеты. Каталог мероприятий, свободные места и запись без сети недоступны — эти данные должны быть свежими. При выходе из аккаунта и смене роли сохранённые для офлайна данные удаляются. Подробности — [`docs-zensical/docs/technical/pwa.md`](docs-zensical/docs/technical/pwa.md).

**Требования к HTTPS.** Браузер даёт доступ к камере и разрешает service worker только на защищённой странице: `https://` или `localhost`.

| Что | `http://IP:3000` | `https://` с самоподписанным сертификатом | `https://` с доверенным сертификатом |
| :--- | :-: | :-: | :-: |
| Живая камера сканера QR | нет | да, после «Всё равно перейти» | да |
| «Сфотографировать QR», ввод кода | да | да | да |
| Service worker, офлайн, кнопка «Установить» | нет | нет | да |
| Ярлык на главный экран, иконка, название | через меню браузера | через меню браузера | да |

Если камера не включается, сканер сам объясняет причину: страница не по HTTPS, доступ запрещён (где разрешить на iPhone и Android), камера не найдена или занята другим приложением. Бесплатный доверенный сертификат — домен и Let's Encrypt (или имя вида `109-196-167-212.sslip.io`, указывающее на IP сервера).

Все проверки делаются на свежей базе (`docker compose down -v && docker compose up --build -d`).

| # | Сценарий | Статус | Как проверить |
| :-: | :--- | :-: | :--- |
| 1 | **Создание с новым видом спорта** | ✅ | Войти как Иван → «Создать» → «+ Свой вид спорта» → ввести, например, «Петанк». Вид получает slug `petank`, попадает в каталог фильтров и `GET /sports` |
| 2 | **Допуск организации и публикация** | ✅ | Клуб «Ладья» пытается создать событие — блокировка. Администратор → «Организации» → «Одобрить»; клуб публикует событие сразу, без премодерации. Новую организацию можно зарегистрировать на `/auth` |
| 3 | **Свободное присоединение** | ✅ | Ольга открывает «Воркаут: тренировка и разбор базы» (режим «свободный вход») и записывается — статус сразу «Участие подтверждено», счётчик мест растёт |
| 4 | **Участие по заявке** | ✅ | У «Дворового футбола 5x5» уже есть заявка Алексея. Иван (автор) → «Мои события» → «Я организую» → «Заявки» → «Принять» или «Отклонить». Алексей видит новый статус |
| 5 | **Уточнение условий (чат под событием)** | ✅ | Ольга или Алексей пишет вопрос в «Обсуждении» под «Дворовым футболом 5x5»; Иван (автор) отвечает — ответ появляется со значком «Организатор». Уже есть демо-диалоги под «Утренним забегом на о. Татышев» и «Дворовым футболом». Администратор скрывает сообщение — остальные видят «Сообщение скрыто модератором» |
| 6 | **Снятие с публикации админом** | ✅ | Администратор → «Мероприятия» → «Снять с публикации» с причиной. Событие исчезает из каталога, карты и рекомендаций; по прямой ссылке видна плашка с причиной, запись закрыта. Пример: [`/events/5`](http://localhost:3000/events/5) |

## ⚠️ Текущие ограничения

* **Push-уведомления** не реализованы; центр уведомлений в приложении есть (опрос каждые 20 секунд). Уведомления об ответах в обсуждении пока нет.
* **PWA** есть (установка, офлайн-оболочка, билеты без сети), но service worker работает только с доверенным сертификатом: на самоподписанном браузер его не регистрирует — см. [PWA, HTTPS и камера](#-pwa-https-и-камера).
* Код билета постоянный (вход по нему одноразовый): скриншот QR, отправленный другому, пропустит того, кто придёт первым. Динамического QR нет.
* Обсуждение обновляется опросом раз в 8 секунд, без WebSocket.
* Число занятых мест в списке карты может отставать до 60 секунд (TTL кэша в Redis); карточка мероприятия всегда точная.
* Интересы не запрашиваются при регистрации — их указывают в тесте «Компас интересов» (его предлагает обучающий тур), в профиле или на странице рекомендаций.
* Повторяющееся мероприятие создаёт следующее занятие только когда организатор завершает текущее; расписание наперёд не строится, а участники на новое занятие не переносятся.
* Напоминание одно — за сутки до начала; других сроков и каналов (push, e-mail) нет.
* Прогноз погоды (Open-Meteo) и часть фото обложек (Unsplash) подгружаются из внешних сервисов: без интернета они не показываются, остальное работает.
* Задел «Поделиться геопозицией»: в конфигурации есть флаг `features.location-sharing.enabled`, кода под ним пока нет.
* Для демо CORS открыт для всех источников, кэш рекомендаций хранится в памяти процесса, загрузки лежат на диске (volume). Что менять при росте нагрузки — в [`docs/architecture.md`](docs/architecture.md#10-ограничения-и-развитие).
* Без ключа 2GIS карта заменяется заглушкой; остальной интерфейс работает.
