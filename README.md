# 🏆 Sportikus — Платформа спортивных активностей

> **Финал Чемпионата России по продуктовому программированию (ФСП, кейс Столото)**
> **Миссия:** от идеи потренироваться к конкретной компании за 2 клика — в любом городе страны.

## ✨ Возможности

## 🛠️ Стек технологий

* **Backend:** Java 21, Spring Boot 3.3, Spring Data JPA, Spring Security (JWT), Flyway, Springdoc OpenAPI (Swagger UI).
* **База данных:** PostgreSQL 16 + **PostGIS** (геопоиск, материализованные представления, секционированный журнал).
* **Frontend:** React 19, Vite, TypeScript, Tailwind CSS 4, React Router, карты **2GIS MapGL JS API**, Lucide Icons.
* **DevOps:** Docker, Docker Compose, Nginx.

## 🚀 Быстрый запуск

Нужен запущенный **Docker Desktop**. В корне проекта:

```bash
# 1. (необязательно) ключ карт 2GIS — без него приложение работает, но вместо карты будет заглушка
cp .env.example .env
#    откройте .env и впишите VITE_2GIS_KEY (получить: https://platform.2gis.ru)

# 2. Сборка и запуск базы, бэкенда и веб-клиента
docker compose up --build -d

# 3. Проверка состояния
docker compose ps
```

> Ключ 2GIS встраивается в фронтенд **при сборке**, поэтому после его изменения нужна пересборка: `docker compose up --build -d`.

## 🧑‍💻 Разработка без Docker

Для бэкенда нужны **Java 21**, **Maven 3.9+** и PostgreSQL **с расширением PostGIS** — обычный PostgreSQL не подойдёт (миграция выполняет `CREATE EXTENSION postgis`). Проще всего поднять только базу из compose:

```bash
docker compose up -d postgres
```

```bash
# Backend (http://localhost:8080)
cd backend
mvn spring-boot:run
```

```bash
# Frontend (http://localhost:5173)
cd frontend
npm install
npm run dev
```

Vite проксирует запросы `/api` на `http://localhost:8080`. Ключ 2GIS берётся из `.env` в корне проекта или из `frontend/.env` (`frontend/.env` приоритетнее). Подробнее — в [`frontend/README.md`](frontend/README.md).

Полный пример — [`.env.example`](.env.example).

## 🧩 Конструктор мероприятий

Создание мероприятия (`/events/new`) собирается из блоков, а формат мероприятия описывается **данными, а не кодом**:

1. **Шаблон** (`GET /api/v1/templates`): «Тренировка», «Игра / матч», «Турнир», «Забег» (только для организаций), «Интеллектуальная игра», «Поход», «Мастер-класс» (не спорт) и «Свободный формат». Шаблон задаёт значения по умолчанию, набор дополнительных полей (`TEXT`, `TEXTAREA`, `NUMBER`, `SELECT`, `MULTISELECT`, `BOOLEAN`) и вопросы участнику. Новый формат — это одна строка в таблице `event_templates` (JSON-схема полей), без правок кода.
2. **Вид спорта:** выбор из списка или «+ Свой вид спорта» — название нормализуется в slug (`Воркаут` → `vorkaut`) и сразу попадает в общий каталог и фильтры.
3. **Свои параметры:** произвольные пары «название — значение» поверх шаблона.
4. **Анкета участника:** организатор сам добавляет вопросы (текст, число, выбор, да/нет), на которые отвечает подающий заявку. Поля шаблона копируются в мероприятие снимком, поэтому правки шаблона не ломают уже созданные события.
5. **Данные организатора** (только для организаций, контакты обязательны): контактное лицо, телефон/e-mail, сайт или регламент, площадка, медицинская справка и страховка, список документов, призы, программа, инфраструктура, условия отмены, партнёры. Если заданы требования, участник подтверждает ознакомление при подаче заявки.
6. **Место и время:** точка выбирается кликом по карте; время вводится **по местному времени площадки** (город и часовой пояс определяются по точке).

Публикует мероприятие пользователь — от своего имени; организатор — от имени организации, **только после одобрения** администратором (иначе `403`).

## ✅ Участие с подтверждением

| Режим | Что происходит при записи |
| :--- | :--- |
| `APPROVAL` (по умолчанию) | Создаётся заявка `PENDING` с анкетой и сообщением. Место занимает только подтверждённая заявка: организатор принимает (`CONFIRMED`) или отклоняет (`REJECTED`, с комментарием) на `/events/:id/manage` |
| `OPEN` | Запись подтверждается сразу (`CONFIRMED`) |

Перед отправкой участник видит диалог подтверждения: время, место, цену, требования и анкету. Дальше — состояния «Заявка на рассмотрении» → «Вы участвуете» / «Заявка отклонена». Участник может отозвать заявку или отменить участие и записаться снова; организатор может исключить подтверждённого участника. Места выдаются под блокировкой строки мероприятия — последнее место нельзя занять дважды. Проверяются: собственное мероприятие, снятие с публикации, завершение, закрытая регистрация, повторные заявки.

## 🎯 Рекомендации

Страница **«Рекомендовано для вас»** (`/recommended`, пункт **«Для вас»** в верхнем меню и в нижней панели на телефоне; нужен вход) подбирает мероприятия по интересам, месту, времени и истории пользователя. Каждая карточка показывает причины, а кнопка «Не интересно» скрывает событие и понижает похожие (с возможностью отмены).

**Как это работает** (подробно — в [`docs/architecture.md`](docs/architecture.md#6-рекомендательная-система)):

* **Без Elasticsearch.** Всё считается внутри бэкенда на данных PostgreSQL + PostGIS: данные всегда свежие (свободные места, статус, заявки), нет синхронизации индекса.
* **Кандидаты из четырёх источников** (интересы, популярное рядом, знакомые организаторы, ближайшие по времени) — каждый с лимитом, поэтому даже плотный город не перегружает расчёт.
* **Прозрачное ранжирование** (`weighted-v1`): интерес, расстояние, накопленный интерес, срочность, уровень, популярность, организатор, удобное время — по местному времени площадки; штраф за отвергнутое; не больше двух событий одного вида подряд.
* **Сигналы поведения** с затуханием (период полураспада 90 дней) и «похожие виды спорта» по поведению других пользователей.
* **Холодный старт:** без интересов показывается популярное рядом; без местоположения — предложение указать город или разрешить геолокацию.
* **Точка поиска:** геолокация устройства → домашняя точка → центр домашнего города.
* **Кэш** выдачи на 2 минуты со сбросом при действиях пользователя; **фоновые задачи** (популярность каждые 5 минут, ночной пересчёт сигналов) безопасны при нескольких экземплярах бэкенда.
* **Журнал** показов, кликов, отказов и записей (`recommendation_log`) — основа для метрик и будущей обученной модели.

Интересы задаются через `PUT /api/v1/me/preferences` (вид спорта, город, радиус, уровень, удобное время, бюджет, год рождения); в интерфейсе их собирает блок **«Мои интересы»** в личном профиле (`/profile`) и кнопка «Мои интересы» на странице рекомендаций — это одна и та же форма. Регистрация интересы не запрашивает: до первого заполнения пользователь видит популярное рядом и приглашение указать интересы.

Настройка без пересборки — `application.yml`:

```yaml
recommendations:
  default-radius-km: 25        # радиус поиска, если пользователь не задал свой
  horizon-days: 30             # рекомендуем события на ближайшие N дней
  candidates-per-source: 300   # лимит кандидатов с одного источника
  cache-ttl: PT2M
  max-same-sport-in-row: 2
  affinity-half-life-days: 90
  weights: { interest: 0.35, distance: 0.20, affinity: 0.15, urgency: 0.10,
             skill: 0.08, social: 0.07, organizer: 0.05, time: 0.05, dislike-penalty: 0.30 }
  jobs: { enabled: true, popularity-refresh: PT5M, nightly-cron: "0 30 3 * * *" }
```

## 👥 Аккаунты, организации и профили

* **Регистрация** (`/auth`): пользователь — имя, фамилия, e-mail, пароль (8–72 символа), доступ сразу; организация — название, ИНН (10/12 цифр), ОГРН (13/15), КПП (9), e-mail, пароль. Организация создаётся в статусе `PENDING`: публиковать мероприятия можно только после одобрения администратором, отказ приходит с причиной. ИНН и ОГРН уникальны.
* **Профили** (`/profile`, `/profiles/users/:id`, `/profiles/organizations/:id`): публичная страница с текущими мероприятиями; владелец редактирует имя, описание организации и загружает фото или логотип (JPG, PNG, WebP до 5 МБ). Профиль неодобренной организации виден только владельцу и администратору.
* **Интересы** (в собственном профиле пользователя): виды спорта, город, радиус поиска, уровень, удобное время, бюджет, год рождения. Сводка и форма редактирования; от них зависит страница «Для вас».
* **Личный кабинет** (`/my`): «Я участвую» (заявки и их статусы) и «Я организую» (мероприятия и число заявок в ожидании).
* **Модерация** (`/admin`): организации (одобрить / отклонить с причиной), мероприятия (снять с публикации с причиной / вернуть; фильтры «⚠ Требуют внимания» и «Отклонены автопроверкой», кнопка «Проверено») и комментарии (скрыть).

## 💬 Обсуждение под событием

На странице каждого мероприятия есть блок «Обсуждение и вопросы» — здесь участники уточняют условия, а организатор отвечает.

* **Читать** обсуждение можно без входа, **писать** — после входа (до 2000 символов; `Enter` — отправить, `Shift+Enter` — новая строка).
* Сообщения организатора мероприятия (автор события или владелец организации) помечаются значком **«Организатор»** — ставит бэкенд, а не клиент.
* Обновляется автоматически (опрос каждые 8 секунд).
* **Скрыть сообщение** может администратор, автор сообщения и организатор мероприятия. Скрытие мягкое: запись остаётся в БД, обычные пользователи видят «Сообщение скрыто модератором», настоящий текст — только администратор.
* Администратор видит все комментарии платформы с названиями мероприятий на вкладке «Комментарии» в `/admin`.

## 🤖 Автопроверка мероприятий

Каждое новое мероприятие проверяется автоматически — для автора это несколько секунд после нажатия «Опубликовать» (кнопка показывает «Публикуем и проверяем…»).

```
создание ─▶ фильтр запрещённых тем ─┬─ ничего не нашёл ──────────▶ опубликовано сразу
                                     └─ сомнение ─▶ проверка ИИ ─┬─ отклонено ─▶ не опубликовано, автор видит причину
                                                                 ├─ одобрено  ─▶ опубликовано с пометкой ⚠ для администратора
                                                                 └─ ИИ недоступен ─▶ опубликовано с пометкой ⚠ («нужна ручная проверка»)
```

1. **Фильтр запрещённых тем** (`BannedWordFilter`) ищет по словарю политику, алкоголь, табак и вейпы, наркотики и допинг, азартные игры и ставки, дискриминацию и оскорбления, насилие и экстремизм, контент 18+, финансовые схемы и спам, нецензурную лексику. Проверяются все текстовые поля: название, описание, вид спорта, параметры шаблона, свои поля, вопросы участникам, сведения организации, адрес. Обходы вроде «вoдкa» с латинскими буквами, «в0дка», «в.о.д.к.а» и «в о д к а» тоже ловятся. Фильтр не выносит приговор — он только поднимает сомнение. Кроме того, всегда проверяются ИИ мероприятия со **своим видом спорта** и в категории **«Другое»**: словарь не может оценить их тематику.
2. **Проверка ИИ** (`RouterAiModerationClient`) — запрос к [RouterAI](https://routerai.ru) (OpenAI-совместимый шлюз), модель по умолчанию **`google/gemini-2.5-flash-lite`**: быстрая (без «размышлений»), недорогая — порядка сотых долей рубля за проверку — и хорошо понимает русский. Модель решает, относится ли мероприятие к спорту, активности или ЗОЖ и нет ли нарушений; упоминание в запрещающем смысле («без алкоголя») не считается нарушением. Ответ — строго JSON с решением и причиной для автора. Текст мероприятия передаётся как данные, а не инструкции. Таймаут — 8 секунд.
3. **Итог.** Пока идёт проверка, мероприятие скрыто (статус `MODERATION`) и нигде не показывается. Отклонённое ИИ получает статус `UNPUBLISHED` с причиной «Не прошло автоматическую проверку: …» — автор видит её сразу на форме и в «Моих событиях». Одобренное ИИ публикуется, но в `/admin` → «Мероприятия» помечается знаком **⚠** с объяснением модели и найденными словами; администратор нажимает «Проверено» или снимает мероприятие с публикации. Ошибочно отклонённое можно вернуть кнопкой «Вернуть». Если ИИ недоступен (нет ключа, таймаут), добросовестный автор не ждёт — мероприятие публикуется с пометкой ⚠ «нужна ручная проверка».

Проверка ИИ выполняется вне транзакции, поэтому БД во время ожидания не блокируется. Если бэкенд перезапустился посреди проверки, фоновая задача доделает её в течение минуты.

Настройки — `application.yml`, секция `moderation`: выключатель всей проверки (`MODERATION_ENABLED`), ключ (`ROUTERAI_API_KEY`), модель (`MODERATION_LLM_MODEL`), таймаут, список видов спорта для обязательной проверки. Модель можно заменить любой из [каталога RouterAI](https://routerai.ru/models) без изменения кода, например на `deepseek/deepseek-v4.1-flash`.

## 📡 API

Полная интерактивная документация — **Swagger UI** (см. [ссылки](#-доступные-сервисы)). Авторизация: `POST /api/v1/auth/login` → кнопка **Authorize** → вставить `token`. Ошибки всегда в формате `{"error": {"code": "...", "message": "..."}}`.

| Группа | Методы и пути | Доступ |
| :--- | :--- | :--- |
| **Auth** | `POST /auth/login` · `POST /auth/register/user` · `POST /auth/register/organization` | публично |
| | `GET /auth/me` | токен |
| **Profiles** | `GET /profiles/users/{id}` · `GET /profiles/organizations/{id}` | публично |
| | `PATCH /profiles/users/{id}` · `PATCH /profiles/organizations/{id}` · `POST …/{id}/image` (multipart) | владелец |
| **Каталог** | `GET /events` (фильтры `sport`, `q`, `skillLevel`, `joinMode`, `template`, `lat`, `lng`, `radiusKm`) · `GET /events/{id}` · `GET /events/{id}/ics` | публично |
| | `GET /sports` · `GET /templates` · `GET /cities` · `GET /cities/nearest` | публично |
| | `POST /events` | токен; организация — только одобренная |
| **Обсуждение** | `GET /events/{id}/comments` | публично |
| | `POST /events/{id}/comments` · `PATCH /events/{id}/comments/{commentId}/hide` | токен; скрыть — админ, автор или организатор |
| **Участие** | `POST /events/{id}/join` · `DELETE /events/{id}/join` | токен |
| | `GET /events/{id}/participations` · `PATCH /events/{id}/participations/{pid}` | организатор мероприятия |
| **Личный кабинет** | `GET /me/participations` · `GET /me/events` | токен |
| | `GET /me/preferences` · `PUT /me/preferences` | токен |
| **Рекомендации** | `GET /recommendations` (`lat`, `lng`, `limit`) | токен |
| | `POST /recommendations/feedback` (`CLICK` / `DISMISS`) · `DELETE /recommendations/feedback/{eventId}` | токен |
| **Admin** | `GET /admin/organizations` · `POST /admin/organizations/{id}/approve` · `…/reject` | `ROLE_ADMIN` |
| | `GET /admin/events` (с результатом автопроверки, помеченные ⚠ — первыми) · `POST /admin/events/{id}/unpublish` · `…/publish` | `ROLE_ADMIN` |
| | `POST /admin/events/{id}/moderation/reviewed` — снять пометку ⚠ | `ROLE_ADMIN` |
| | `GET /admin/comments` | `ROLE_ADMIN` |

Все пути — с префиксом `/api/v1`. Загруженные изображения отдаются по `/uploads/{uuid}.{ext}`.

## 🧭 Покрытие 6 обязательных сценариев ТЗ

Все проверки делаются на свежей базе (`docker compose down -v && docker compose up --build -d`).

| # | Сценарий | Статус | Как проверить |
| :-: | :--- | :-: | :--- |
| 1 | **Создание с новым видом спорта** | ✅ | Войти как Иван → «Создать» → «+ Свой вид спорта» → ввести, например, «Петанк». Вид получает slug `petank`, попадает в каталог фильтров и `GET /sports` |
| 2 | **Допуск организации и публикация** | ✅ | Клуб «Ладья» пытается создать событие — блокировка. Администратор → «Организации» → «Одобрить»; клуб публикует событие сразу, без премодерации. Новую организацию можно зарегистрировать на `/auth` |
| 3 | **Свободное присоединение** | ✅ | Ольга открывает «Воркаут: тренировка и разбор базы» (режим «свободный вход») и записывается — статус сразу «Участие подтверждено», счётчик мест растёт |
| 4 | **Участие по заявке** | ✅ | У «Дворового футбола 5x5» уже есть заявка Алексея. Иван (автор) → «Мои события» → «Я организую» → «Заявки» → «Принять» или «Отклонить». Алексей видит новый статус |
| 5 | **Уточнение условий (чат под событием)** | ✅ | Ольга или Алексей пишет вопрос в «Обсуждении» под «Дворовым футболом 5x5»; Иван (автор) отвечает — ответ появляется со значком «Организатор». Уже есть демо-диалоги под «Утренним забегом на о. Татышев» и «Дворовым футболом». Администратор скрывает сообщение — остальные видят «Сообщение скрыто модератором» |
| 6 | **Снятие с публикации админом** | ✅ | Администратор → «Мероприятия» → «Снять с публикации» с причиной. Событие исчезает из каталога, карты и рекомендаций; по прямой ссылке видна плашка с причиной, запись закрыта. Пример: [`/events/5`](http://localhost:3000/events/5) |

## ⚠️ Текущие ограничения

* **PWA** (манифест, офлайн) и push-уведомления — не реализованы.
* Обсуждение обновляется опросом раз в 8 секунд, без WebSocket; уведомлений об ответах пока нет.
* Интересы не запрашиваются при регистрации — их указывают в профиле или на странице рекомендаций.
* Задел «Поделиться геопозицией»: в конфигурации есть флаг `features.location-sharing.enabled`, кода под ним пока нет.
* Для демо CORS открыт для всех источников, кэш рекомендаций хранится в памяти процесса, загрузки лежат на диске (volume). Что менять при росте нагрузки — в [`docs/architecture.md`](docs/architecture.md#10-ограничения-и-развитие).
* Без ключа 2GIS карта заменяется заглушкой; остальной интерфейс работает.
