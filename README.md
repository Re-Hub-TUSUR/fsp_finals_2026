# 🏆 Sportikus — Платформа спортивных активностей

> **Финал Чемпионата России по продуктовому программированию (ФСП, кейс Столото)**  
> **Миссия:** От идеи потренироваться к конкретной компании за 2 клика.  
> **Город проведения:** Красноярск

---

## 🛠️ Стек технологий

* **Backend:** Java 21, Spring Boot 3.3+, Spring Data JPA, Spring Security, Flyway, PostgreSQL 16, Springdoc OpenAPI (Swagger UI).
* **Frontend:** React 19, Vite, TypeScript, Tailwind CSS, Leaflet + React-Leaflet (карта OpenStreetMap без платных API), Lucide Icons.
* **DevOps:** Docker, Docker Compose, Nginx.

Убедитесь, что запущен **Docker Desktop**, затем в корне проекта выполните:

## 🧩 Конструктор мероприятий

Создание мероприятия (`/events/new`) собирается из блоков, а формат мероприятия описывается **данными, а не кодом**:

1. **Шаблон** (`GET /api/v1/templates`): «Тренировка», «Игра/матч», «Турнир», «Забег» (только для организаций), «Интеллектуальная игра», «Поход», «Мастер-класс» (не спорт) и «Свободный формат». Шаблон задаёт значения по умолчанию, набор дополнительных полей (`TEXT`, `TEXTAREA`, `NUMBER`, `SELECT`, `MULTISELECT`, `BOOLEAN`) и вопросы участнику. Новый формат = одна строка в таблице `event_templates` (JSON-схема полей), без правок кода.
2. **Вид спорта**: выбор из списка или «+ Свой вид спорта» — название нормализуется в slug и сразу попадает в общий каталог.
3. **Свои параметры**: произвольные пары «название — значение» поверх шаблона.
4. **Анкета участника**: организатор сам добавляет вопросы (текст, число, выбор, да/нет), на которые отвечает подающий заявку. Поля шаблона копируются в мероприятие снимком, поэтому позднейшие правки шаблона не ломают созданные события.
5. **Данные организатора** (только для организаций, обязательны контакты): контактное лицо, телефон/e-mail, сайт или регламент, площадка, медицинская справка и страховка, список документов, призы, программа, инфраструктура, условия отмены, партнёры. Если заданы требования, участник подтверждает ознакомление при подаче заявки.

Публикует мероприятие пользователь — от своего имени; организатор — от имени организации, **только после одобрения** администратором (иначе `403`).

## ✅ Участие с подтверждением

| Режим | Что происходит при записи |
| :--- | :--- |
| `APPROVAL` (по умолчанию) | Создаётся заявка `PENDING` с анкетой и сообщением. Место занимает только подтверждённая заявка: организатор принимает (`CONFIRMED`) или отклоняет (`REJECTED`, с комментарием) на `/events/:id/manage`. |
| `OPEN` | Запись подтверждается сразу (`CONFIRMED`). |

Участник перед отправкой видит диалог подтверждения: время, место, цену, требования и анкету. Дальше — состояния «Заявка на рассмотрении» → «Вы участвуете» / «Заявка отклонена». Участник может отозвать заявку или отменить участие (и записаться снова); организатор может исключить подтверждённого участника. Места выдаются под блокировкой строки мероприятия, поэтому последнее место нельзя занять дважды. Проверяются: свои мероприятия, снятые с публикации, завершённые, закрытая регистрация, повторные заявки.

Основные эндпоинты (полная документация — Swagger UI):

| Метод | Путь | Назначение |
| :--- | :--- | :--- |
| `POST` | `/api/v1/auth/login` | Вход, JWT |
| `GET` | `/api/v1/templates`, `/api/v1/sports` | Конструктор и справочник видов спорта |
| `GET` / `POST` | `/api/v1/events` | Каталог с фильтрами / создание мероприятия |
| `GET` | `/api/v1/events/{id}` | Карточка (с состоянием участия текущего пользователя) |
| `POST` / `DELETE` | `/api/v1/events/{id}/join` | Записаться или подать заявку / отменить |
| `GET` | `/api/v1/events/{id}/participations` | Заявки и участники (организатор) |
| `PATCH` | `/api/v1/events/{id}/participations/{pid}` | Принять или отклонить заявку (организатор) |
| `GET` | `/api/v1/me/participations`, `/api/v1/me/events` | Мои заявки / мои мероприятия с числом заявок в ожидании |
| `POST` | `/api/v1/admin/organizations/{id}/approve`, `/reject` | Допуск организации |
| `POST` | `/api/v1/admin/events/{id}/unpublish`, `/publish` | Снять с публикации / вернуть |

> После обновления схемы или демо-данных пересоздайте БД: `docker compose down -v && docker compose up --build -d`.

## 🧭 Покрытие 6 обязательных сценариев ТЗ

1. **Создание с новым видом спорта:** Пользователь вводит «Воркаут» $\rightarrow$ генерируется слаг `vorkaut`, вид спорта сохраняется и появляется в общем фильтре.
2. **Допуск организации и публикация:** Админ одобряет «Клуб Ладья» $\rightarrow$ статус меняется на `APPROVED` $\rightarrow$ организация создает турнир без премодерации.
3. **Свободное присоединение:** В режиме `OPEN` запись подтверждается мгновенно (`CONFIRMED`). Пример: «Утренний забег на о. Татышев» (Ольга).
4. **Участие по заявке:** В режиме `APPROVAL` создается заявка `PENDING`, автор в `/events/:id/manage` одобряет или отклоняет её. Пример: «Дворовый футбол 5x5» (Иван → заявка Алексея).
5. **Чат и обсуждения:** Вопросы под событием с подсветкой бейджа `Организатор`.
6. **Снятие с публикации:** Администратор указывает причину $\rightarrow$ событие снимается с карты и поиска, доступно только по прямой ссылке с плашкой причины.
