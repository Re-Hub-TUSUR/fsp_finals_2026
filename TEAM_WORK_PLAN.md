## 🛠️ Зафиксированные архитектурные решения (ADR)

1. **D1 (API-First под мобилку):** Вся бизнес-логика и безопасность живут на Java-бэкенде. Веб-клиент — лишь один из потребителей API (на React), второй потребитель в будущем — мобильное приложение (React Native / Kotlin / Flutter).
2. **D2/D3 (Фронтенд):** React + Vite + TypeScript + Tailwind CSS + Lucide Icons + PWA-манифест. Mobile-first вёрстка, крупные тач-таргеты ($\ge 44\text{ px}$), читаемый контраст для старшего поколения.
3. **D4 (Бэкенд):** Java 21, Spring Boot 3.2+, Gradle (Kotlin DSL) или Maven, Spring Data JPA, Bean Validation, Spring Security с проверками `@PreAuthorize("@eventPolicy.canJoin(...)")`.
4. **D4c/D4d (Структура):** Package-by-feature (`event`, `participation`, `organization`, `admin`, `sport`, `comment`), Flyway миграции (`V1__init.sql`, `R__demo_data.sql`).
5. **D6/D7/D8 (Гео & Карта):** Leaflet + React-Leaflet (OpenStreetMap, без платных API-ключей), расчет расстояний формулой Haversine в нативном SQL-запросе.
6. **D9/D10 (Авторизация & Демо-вход):** JWT (Bearer) + двойная система быстрого входа:
   * Кнопки «Войти как...» на экране `/login`.
   * Плавающий **Role Switcher в шапке** для мгновенной смены ролей экспертами во время проверки.
7. **D15 (Карта в стиле Blink):**
   * Маркер — круглый «пузырь» с логотипом клуба или аватаром/иконкой спорта с хвостиком.
   * **Главное число на метке:** время до старта («через 40 мин», «2 ч», дата).
   * **Второй бейдж:** свободные места (например: `3/10`), огонек у популярных событий.
   * Клик по маркеру открывает **Bottom Sheet (мини-карточку)** снизу экрана с быстрой записью.
8. **D16 (Архитектурный задел «Поделиться геопозицией»):** Сущность `LocationShare` с TTL и огрублением координат, закрытая фиче-флагом `features.location-sharing.enabled=false`. Демонстрирует жюри зрелость архитектуры (+3 балла за развитие).

### ☕ Участник 2: Backend Lead (Java 21 / Spring Boot 3 Core)
**Фокус:** Архитектура БД, сущности, динамический спорт (`slug`), события, режимы участия.

* **Часы 0–3: Базовый каркас и Миграции**
  * Инициализировать Spring Boot 3 (Java 21, Gradle Kotlin DSL / Maven).
  * Подключить Flyway, настроить `V1__init_schema.sql`:
    * Таблицы: `users`, `organizations`, `sports`, `events`, `participations`.
    * Ограничение `CHECK` в `events`: либо `organizer_user_id IS NOT NULL`, либо `organizer_org_id IS NOT NULL`.
  * Настроить `GlobalExceptionHandler` (`@RestControllerAdvice`) с форматом `{ "error": { "code", "message" } }`.
* **Часы 3–14: Модули `sport`, `event`, `participation`**
  * **Пакет `sport`:**
    * Модель `Sport` (`id`, `name`, `slug`, `is_custom`, `created_by`).
    * Логика нормализации слага: `name.toLowerCase().trim().replace('ё', 'е').replaceAll("\\s+", "-")`.
    * Если пользователь вводит новый вид спорта, сервис ищет по слагу: находит — использует существующий, не находит — создает новый без правок кода!
  * **Пакет `event`:**
    * DTO: `CreateEventRequest`, `EventShortResponse` (для списков/карты), `EventDetailsResponse`.
    * Поля: даты начала/конца, координаты `lat`/`lng`, адрес, `join_mode` (`OPEN` / `APPROVAL`), `skill_level` (`NOVICE`, `AMATEUR`, `PRO`, `ANY`), лимит мест, инвентарь.
    * Валидация прав: если создает организация, проверить `org.status == APPROVED`.
  * **Пакет `participation` (State Machine записи):**
    * `POST /api/v1/events/{id}/join`:
      * Если режим `OPEN` $\rightarrow$ статус сразу `CONFIRMED`.
      * Если режим `APPROVAL` $\rightarrow$ статус `PENDING`.
    * Валидация: автор не может записаться на свое событие; нельзя записаться повторно; проверка лимита мест (`capacity`).
    * `PATCH /api/v1/events/{id}/requests/{requestId}`: автор принимает (`CONFIRMED`) или отклоняет (`REJECTED`) заявку.
* **Часы 14–24: Политики безопасности и Unit/Integration тесты**
  * Реализовать класс политик `EventPolicy`:
    * `canJoin(user, event)`
    * `canManageRequests(user, event)` (только автор события!).
  * Написать интеграционные тесты JUnit 5 + MockMvc на Сценарии 1, 3, 4.
* **Часы 24–36: Мобильная оптимизация API**
  * Убедиться в легковесности DTO для мобильных сетей.

### 🛠️ Участник 3: Backend Developer (Java / Admin, Geo, Comments & Seed)
**Фокус:** Админка, геолокация (Haversine), модерация, комментарии, автозаливка демо-данных.

* **Часы 0–3: Инфраструктура и Docker**
  * Настроить `docker-compose.yml`:
    * Сервис `postgres` (port 5432, volume под данные).
    * Сервис `backend` (Spring Boot, healthcheck по `/actuator/health`).
    * Сервис `frontend` (Nginx).
  * Настроить Springdoc OpenAPI (`/swagger-ui/index.html`).
* **Часы 3–14: Пакеты `admin`, `comment`, `organization`**
  * **Пакет `organization`:**
    * Создание заявки организации (`POST /api/v1/organizations`).
    * Статусы: `PENDING` $\rightarrow$ `APPROVED` | `REJECTED`.
  * **Пакет `admin`:**
    * `GET /api/v1/admin/organizations?status=PENDING` — заявки на рассмотрении.
    * `POST /api/v1/admin/organizations/{id}/approve` — допуск.
    * `POST /api/v1/admin/organizations/{id}/reject` — отклонение с **обязательной** причиной `reason`.
    * `POST /api/v1/admin/events/{id}/unpublish` — снятие события с публикации с причиной. При переходе статус меняется на `UNPUBLISHED`.
  * **Пакет `comment`:**
    * Добавление комментария: если пишет автор события/организация, выставлять флаг `is_organizer = true`.
    * Модерация комментариев: soft-delete админом (`is_hidden = true`, текст заменяется на *«Сообщение скрыто модератором»*).
* **Часы 14–24: Гео-поиск и Экспорт календаря**
  * Нативный SQL-запрос с формулой **Haversine**:
    ```sql
    SELECT e.*, (6371 * acos(cos(radians(:lat)) * cos(radians(e.lat)) * cos(radians(e.lng) - radians(:lng)) + sin(radians(:lat)) * sin(radians(e.lat)))) AS distance_km
    FROM events e
    WHERE e.status = 'PUBLISHED'
    HAVING distance_km <= :radius_km
    ORDER BY distance_km;
    ```
  * Эндпоинт `GET /api/v1/events/{id}/ics` — генерация файла `.ics` (iCalendar) для добавления встречи в календарь iOS / Google в 1 клик!
  * Задел под `LocationShare` (D16): заглушка сервиса и сущность под флагом `features.location-sharing.enabled=false`.
* **Часы 24–36: Идемпотентный сид демо-данных (`R__demo_data.sql` / `CommandLineRunner`)**
  * Загрузка при старте (город по умолчанию — **Красноярск**):
    * 👤 3 пользователя (Иван — любитель, Ольга — новичок, Алексей — профи).
    * 🏛️ 1 организация `APPROVED` («Спортивный клуб Енисей»).
    * ⏳ 1 организация `PENDING` («Шахматный клуб Ладья»).
    * ❌ 1 организация `REJECTED` («Подпольный боксерский клуб», причина: «Не указана площадка»).
